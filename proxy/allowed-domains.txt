# 2026-08-20 — QMD's embedding model. The vault's semantic index had been frozen
# since 14 June; re-registering the collection fixed lexical search, but
# `qmd embed` fails with "fetch failed" because `qmd doctor` reports the model
# cache is missing 3/3 — the GGUF weights come from HuggingFace. Read-only model
# downloads. Only the 300M embedding model is needed for indexing; the 1.7B
# generation model is the query expander AGENTS.md already tells me to avoid.
#
# NOTE THE FORM — dotted only, never both. My first attempt at this append
# listed `huggingface.co` AND `.huggingface.co`, which squid 6.13 treats as a
# redundant pair and refuses to parse: "FATAL: Bungled squid.conf". That is a
# fatal error, not a warning, so calproxy crash-looped and took ALL outbound
# traffic down (including api.anthropic.com) from ~18:53–19:01 on 2026-08-20.
# In squid, a leading dot already matches the bare domain AND all subdomains,
# so the dotted form alone is both sufficient and correct. `www.huggingface.co`
# is not enough on its own: it 302-redirects to the bare domain, and the actual
# model files come from CDN hosts under both domains.
.huggingface.co
.hf.co

# 2026-08-21 — Garmin's SSO host. `connect.garmin.com` and
# `connectapi.garmin.com` are already allowed, but every login strategy in
# garminconnect authenticates against sso.garmin.com first, so garmin-sync
# fails at login with a 403 CONNECT tunnel error and never reaches the two
# hosts that ARE allowed. Needed for the Oxford Half training check-ins.
#
# BARE form on purpose. `.garmin.com` would match the two existing bare
# garmin.com entries above and be the exact redundant-pair error that took
# all egress down on 2026-08-20 — a dotted entry here would be fatal.
sso.garmin.com

# 2026-08-25 — the last two Garmin hosts the login flow needs. With
# sso.garmin.com live, authentication now SUCCEEDS and returns a CAS service
# ticket, then dies one step later converting that ticket into a session:
#
#   diauth.garmin.com          — DI OAuth2 token exchange, the preferred path
#                                (garminconnect client.py:112). Currently 403s,
#                                so the library logs "DI token exchange failed"
#                                and drops to the JWT_WEB fallback.
#   mobile.integration.garmin.com
#                              — the iOS/Android service URL the fallback then
#                                GETs to consume the ticket (client.py:49,57).
#                                Also 403s, so no JWT_WEB cookie is ever set and
#                                login fails with "JWT_WEB cookie not set after
#                                ticket consumption".
#
# Both BARE, for the same reason as sso.garmin.com above: a dotted `.garmin.com`
# would cover the four bare garmin.com entries already in this file and is the
# exact redundant-pair error that took all egress down on 2026-08-20.
diauth.garmin.com
mobile.integration.garmin.com
